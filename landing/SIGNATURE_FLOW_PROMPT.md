# ПРОМПТ: Тест-страница модалки заказа отчёта с флоу подписи

## 1. Контекст и цель

В проекте Zelscan есть модалка заказа отчёта (тарифы → оплата). Нужно добавить **обязательную подпись пользователя** перед оплатой. Задача — создать тестовую страницу `signature-flow-test.html`, на которой будут представлены **4 варианта флоу оставления подписи** с возможностью переключения между ними, чтобы выбрать лучший для продакшена.

Подпись — юридически значимый элемент (пользователь соглашается с условиями заказа). Поэтому она обязательна, не может быть пропущена, и UX должен быть максимально понятным.

---

## 2. Дизайн-констрейнты (из проекта, нарушать нельзя)

- Тёмная тема: фон `#020202`, карточки `rgba(255,255,255,0.03–0.05)`
- Шрифт Inter, начертания только **400 (regular) и 500 (medium)**. Semibold/bold запрещены
- Нет лишнего UPPERCASE (только бейджи типа GOOD)
- Скругления: карточки 32px, кнопки 12–16px, инпуты 13–16px
- Цвет текста: основной `#EBEBEB`, вторичный `#6B6B6B`/`#A8A8A8`, placeholder `#424242`
- Акцент: зелёный `#34D399` (success), красный `#EF4444` (error), белый как основной CTA
- Кнопка primary: белый фон `#fff`, текст `#020202`, font-weight 500
- Анимации: `transition .15–.2s ease`, transform-origin у поповеров от точки открытия
- Модалки: `border-radius: 24–28px`, фон `rgba(24,22,21,.98)` или градиент + `backdrop-filter: blur(28px)`
- Без `box-shadow` на интерактивных мелких элементах (убрано из дизайн-системы), только на больших оверлеях

## 3. Механика подписи (общая для всех вариантов)

### Canvas-пэд подписи
- Поле для рисования, пропорция примерно **3:1** (например 460×160px)
- Фон поля: `rgba(255,255,255,0.02)`, border `1px dashed rgba(255,255,255,0.15)`, radius 16px
- Линия-подсказка по центру (как строка в тетради): пунктир `rgba(255,255,255,0.08)`, подпись должна визуально «садиться» на неё
- Курсор: `crosshair` на десктопе
- Рисование: pointer events (mouse + touch + pen), `pointerdown/move/up`, `setPointerCapture`
- Линия: `strokeStyle: #EBEBEB`, `lineCap: round`, `lineJoin: round`
- Retina: canvas масштабируется через `devicePixelRatio`, чтобы подпись не была мыльной

### Выбор толщины кисти
- 3 варианта: тонкая (1.5px), средняя (2.5px), жирная (4px)
- UI: три кружка-превью разного диаметра, активный — с обводкой/фоном
- Переключение мгновенное, не стирает нарисованное
- По умолчанию: средняя

### Кнопки пэда
- **«Очистить»** — стирает весь canvas (с подтверждением? — нет, мгновенно, но canvas маленький, потерять не жалко). Ghost-стиль
- **«Готово»** — сохраняет подпись. Disabled, пока canvas пустой. Primary белая
- **«Отмена»/✕** — закрывает пэд без сохранения. Ghost-стиль

### Валидация «подпись оставлена»
- Минимум: хотя бы 1 pointer stroke (набор точек)
- Дополнительно (вариант для теста): минимум N пикселей закрашено (например 50) — защита от случайного тычка
- «Готово» активна только при наличии рисунка

## 4. Четыре варианта флоу (все на одной тест-странице, переключатель сверху)

### Вариант A — Inline-раскрытие (без оверлея)
Внутри модалки под оплатой — блок «Подпись (обязательно)» с превью-плейсхолдером. Клик → блок **плавно разворачивается** (height animation) в полноценный canvas-пэд прямо в потоке модалки. После «Готово» блок сворачивается обратно до превью подписи.
- Плюсы: нет слоёв, всё в одном контексте
- Минусы: модалка прыгает по высоте, мало места для пэда

### Вариант B — Оверлей поверх модалки (рекомендуемый)
Клик по плейсхолдеру → поверх модалки появляется **dimmed-оверлей** (`rgba(0,0,0,.5)` + blur 8px на фоне) с центрированной карточкой пэда (radius 24px). Исходная модалка видна за blur, но неактивна (inert). «Готово»/отмена → оверлей уходит с fade, в модалке появляется превью подписи.
- Плюсы: много места, фокус на задаче, привычный паттерн
- Минусы: второй слой поверх первого

### Вариант C — Отдельный шаг в модалке
Модалка становится пошаговой: Шаг 1 «Тариф и оплата» → кнопка «Далее» → Шаг 2 «Подпись» (canvas во всю ширину модалки) → «Подтвердить и оплатить». Индикатор шагов сверху (2 точки или «1/2»). Кнопка «Назад» на шаге 2.
- Плюсы: линейный wizard, сложно ошибиться
- Минусы: лишний шаг, дальше от контекста заказа

### Вариант D — Bottom sheet (мобильный паттерн)
Плейсхолдер в модалке → клик → снизу экрана выезжает **шит** (slide-up, spring easing) с пэдом во всю ширину. Свайп вниз / тап по scrim — закрыть без сохранения. На десктопе шит центрирован снизу, ширина ~520px.
- Плюсы: большой пэд, отлично на тачах
- Минусы: непривычно на десктопе

## 5. Полный user flow (детально, по этапам)

1. **Вход**: пользователь на странице, кликает «Заказать отчёт»
2. Модалка открывается: тарифы (3 шт), один предвыбран
3. Пользователь листает/выбирает тариф → цена обновляется
4. Блок оплаты: метод (карта/крипта и т.п.)
5. **Блок подписи**: заголовок «Подпись» + бейдж «обязательно» (красный или серый muted, НЕ агрессивный)
   - Пустое состояние: плейсхолдер-прямоугольник с иконкой пера и текстом «Нажмите, чтобы оставить подпись»
6. Клик по плейсхолдеру → открывается пэд (по выбранному варианту A/B/C/D)
7. Пользователь выбирает толщину (или оставляет среднюю)
8. Рисует подпись
   - Ошибся → «Очистить» → рисует заново
   - Передумал → «Отмена» → пэд закрывается, плейсхолдер снова пустой
9. «Готово» → пэд закрывается → в блоке появляется **превью подписи** (уменьшенный canvas→image, contain, высота ~60px) + подпись «Подпись сохранена» зелёным + кнопка «Изменить» (открывает пэд с уже загруженной подписью, можно дорисовать или очистить)
10. Кнопка «Оплатить N ₽» становится активной **только после сохранённой подписи**
11. Клик «Оплатить» → loading-спиннер на кнопке → успех (тест: экран «Заказ принят, подпись приложена»)

## 6. Состояния UI (все должны быть отрисованы)

**Блок подписи:**
- `empty` — плейсхолдер, пунктирная рамка
- `empty-hover` — рамка светлеет, фон чуть плотнее, курсор pointer
- `filled` — превью подписи + «Изменить»
- `error` — красная рамка `rgba(239,68,68,.4)` + текст «Оставьте подпись, чтобы продолжить» (появляется при попытке оплатить без подписи) + лёгкий shake (translateX ±4px, 3 итерации, .3s)

**Пэд:**
- `empty` — кнопка «Готово» disabled (opacity .4, cursor default)
- `drawing` — активное рисование
- `dirty` — есть рисунок, «Готово» активна, «Очистить» активна

**Кнопка «Оплатить»:**
- `disabled` (нет подписи) — opacity .5, cursor not-allowed. При клике на disabled — shake на блоке подписи + error-сообщение (не молча игнорить!)
- `enabled`
- `loading` — спиннер + «Оформляем…»

## 7. Ошибки и edge cases (обязательно обработать на тест-странице)

1. **Оплата без подписи** → shake + error-текст у блока подписи (вариант A/B/D) или блокировка кнопки «Далее» (вариант C — там это шаг, поэтому просто «Готово» disabled)
2. **Отмена в пэде после рисования** → ничего не сохраняется, плейсхолдер пустой. Вопрос: показывать ли confirm «Подпись будет потеряна»? Решение для теста: в варианте B — показать, в остальных — нет (сравнить)
3. **«Изменить» подпись** → пэд открывается с текущей подписью на canvas (можно стереть/дорисовать)
4. **Очистка уже сохранённой подписи в режиме «Изменить»** → «Готово» снова disabled → пользователь не может сохранить пустую подпись; если нажмёт «Отмена» — старая подпись остаётся
5. **Тычок-точка** (один tap) → считается подписью или нет? Тестовый переключатель «строгая валидация» (min 50px закрашено)
6. **Ресайз окна** → canvas пересоздаётся, нарисованное НЕ должно теряться (перерисовка из сохранённых строок или image)
7. **Двойной клик «Готово»** → debounce/lock, чтобы не было двойного сабмита
8. **Закрытие модалки с заполненной подписью** → при повторном открытии подпись сохранена (in-memory, без бэка) или сброшена — сделать переключателем на тесте, решить какое поведение лучше
9. **Тач-скролл** в пэде на мобильном → `touch-action: none` на canvas, чтобы палец рисовал, а не скроллил
10. **Очень длинная подпись** (тысячи точек) → оптимизация: throttle на pointermove (requestAnimationFrame), сглаживание линии через quadratic curves

## 8. Технические требования

- Чистый HTML/CSS/JS в одном файле `signature-flow-test.html` (без фреймворков)
- Canvas: хранить историю строок (массив массивов точек + толщина) — для ресайза и потенциального undo
- Превью подписи: `canvas.toDataURL('image/png')` → `<img>` в блоке (trim прозрачных полей — crop по bounding box рисунка + padding 8px)
- Переключатель вариантов A/B/C/D сверху страницы — segmented control (как `.tabs` в проекте), при переключении состояние подписи сохраняется
- Дополнительный переключатель «строгая валидация» и «сохранять при закрытии модалки» — для демонстрации edge cases
- Кнопка «Сбросить всё» на тест-странице — полный reset состояния
- Адаптив: при ≤640px вариант D должен работать жестами (свайп вниз), остальные просто не ломаться
- Логи событий в консоль/на экран (панель event log справа): `signature_open`, `stroke_start`, `stroke_end`, `clear`, `save`, `cancel`, `pay_attempt_no_sign` — для анализа флоу

## 10. Acceptance criteria (что проверить на ревью)

- [ ] Все 4 варианта флоу работают и переключаются без перезагрузки
- [ ] Подпись рисуется мышью и тачем, линия гладкая, без углов
- [ ] Толщина кисти переключается и видна разница
- [ ] «Очистить» стирает полностью
- [ ] «Готово» disabled на пустом canvas во всех вариантах
- [ ] Оплата без подписи → error-состояние, без молчаливой блокировки
- [ ] «Изменить» возвращает подпись в пэд
- [ ] Превью подписи обрезано по содержимому (без пустых полей)
- [ ] Состояние переживает ресайз окна
- [ ] Визуально — 1 в 1 дизайн-система проекта (цвета, радиусы, шрифты, веса)
- [ ] Event log фиксирует все события с таймстемпами

## 11. Что НЕ делать

- Не добавлять загрузку подписи файлом (только рисование)
- Не делать «напечатать имя вместо подписи» (отдельная фича, не в этой задаче)
- Не сохранять подпись на бэкенд (тест — только in-memory)
- Не использовать сторонние библиотеки для подписи (signature_pad и т.п.) — свой минимальный код, чтобы потом перенести в проект
